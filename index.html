Two ways to boot

Headless, or full desktop.

One ISO, picked in the bootloader. The server personality and the desktop personality ship together.

DEFAULT

Headless CLI

Minimal console system, no GUI packages. The router / NAS / always-on server personality. Small, quiet, runs forever.

castle.mode=cli

OPTION

GUI on Wayland

labwc stacking compositor, foot terminal, wofi launcher. Boots straight into the desktop on first login.

castle.mode=gui

Built-in versioning

Every file gets a history.

Chains is version control for files, baked into the OS. Enable a vault on any directory and every change is journaled. Delete something by accident, rewind it.

  • Git for files. Snapshots and history for anything, not just code.
  • Zero build changes. Ships on the live system as /opt/castle/chains.
  • Dependency-free. Bash engine with regression suites, runs anywhere.
$ chains init /data/vault vault created · journal at /data/vault/.chains $ chains snap "before the edit" snapshot 12 · 2,048 files journaled $ chains log 12 before the edit 2m ago 11 nightly sync 9h ago 10 first snapshot 2d ago

Get it

Flash it tonight.

ISOs build automatically from the repo. Grab the latest artifact, flash a USB, boot.

# build it yourself on any Arch machine
sudo pacman -S archiso
git clone https://github.com/YEAHDOGS/castle-os.git
cd castle-os
./build.sh cli      # headless ISO
./build.sh gui      # GUI ISO
# ISO lands in out/ — flash per docs/RUNBOOK.md

Questions

Straight answers.

What hardware does it run on?

Any x86_64 PC you can boot from USB. An old laptop or a mini-PC makes a great Castle box. Try it live before installing, nothing is touched until you run the installer.

How much does it cost?

Nothing. Castle OS is MIT-licensed and free. No accounts, no tiers, no upsells. Bring your own hardware.

Does it phone home?

No. There is no telemetry, no account system, no analytics in the OS. It is your machine.

How do updates work?

Phase 1 ships the live ISO and installer. A package repository and update channel are phase 2, documented in the repo.

Where do I get help?

The repo has a full runbook covering builds, QEMU testing, and flashing. Issues on GitHub are read.
